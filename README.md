# Ordeus Backend

Серверная часть личного органайзера Ordeus: аккаунты, API для дневника, задач и календаря, фоновый разбор записей нейросетью. Интерфейс лежит в репозитории [Ordeus-frontend](https://github.com/EazyXxX/Ordeus-frontend).

## Стек

Go, `net/http`, PostgreSQL, pgx, goose, air.

## Запуск

Нужны Docker и Go 1.27. Сервер слушает `127.0.0.1:8080`.

```bash
docker compose up -d --wait
go tool air
```

Сервер сам пересобирается и перезапускается при изменении файлов `.go` и `.sql`. Миграции применяются при старте.

База PostgreSQL 18 работает в Docker и доступна только с этой машины: `127.0.0.1:5432`, база, пользователь и пароль `ordeus`.

Тесты запускаются так:

```bash
go test ./...
```

## Структура

```text
cmd/server/            точка входа
internal/ai/           клиент OpenAI-совместимых API (Ollama и внешние)
internal/api/          сборка HTTP-маршрутов
internal/auth/         аккаунты, сессии и личный кабинет
internal/calendar/     календарь: заметки и задачи со сроком
internal/config/       настройки из окружения
internal/database/     подключение к базе и миграции
internal/diary/        дневник: API, база, разбор записей нейросетью
internal/httpjson/     общие помощники для JSON
internal/kanban/       задачи: канбан, API, разбор текста в тикеты
```

## Новый модуль

Добавьте миграцию в `internal/database/migrations/`, создайте пакет в `internal/` и подключите его маршруты к `protected` в `internal/api/api.go`. Все таблицы модуля должны хранить `user_id`, а запросы фильтровать по `auth.UserID(ctx)`.

## Настройки сервера

| Переменная | По умолчанию |
|---|---|
| `ORDEUS_ADDR` | `127.0.0.1:8080` |
| `ORDEUS_DATABASE_URL` | `postgres://ordeus:ordeus@127.0.0.1:5432/ordeus?sslmode=disable` |
| `ORDEUS_SECURE_COOKIES` | `false`, включите при работе через HTTPS |
| `ORDEUS_AI_BASE_URL` | `http://127.0.0.1:11434/v1` |
| `ORDEUS_AI_MODEL` | `gemma4:12b`, пока модель не выбрана в приложении |
| `ORDEUS_AI_API_KEY` | не задан |
| `ORDEUS_SECRET_FILE` | `.ordeus-secret`, создаётся сам. Без него сохранённые ключи вендоров не расшифровать |
| `ORDEUS_UPLOADS_DIR` | `uploads`, картинки заметок, по папке на аккаунт. Бэкапить вместе с базой |
| `ORDEUS_AI_ALLOW_PRIVATE_URLS` | `false`, разрешает API-адреса во внутренней сети |
| `ORDEUS_AI_REASONING_EFFORT` | `none` для локальной Ollama, иначе не отправляется |

## Нейросеть

В дзен-режиме дневника запись раскладывается на заголовок, папку, теги, связи и дату дейли-заметки, а новым папкам и тегам подбираются эмодзи. Нейросеть не меняет эмодзи, который автор выбрал или убрал. Заголовок дейли-заметки начинается с её дня, например «08.11.2026 — …»: дату ставит сервер, а не модель. В дзен-режиме задач текст превращается в тикеты с описанием, сроком и категорией: нейросеть берёт существующую категорию автора, а новую заводит, только если ни одна не подходит. В дзен к записи можно приложить до 10 фото: модель смотрит на первые три (WebP и GIF сервер перерисовывает в JPEG), берёт из них заголовок, папку и теги, а все фото прикрепляет к первой заметке. Запись из одних фото становится одной заметкой с коротким описанием. Если модель не видит картинок, запись с текстом разбирается без них. Коррекция исправляет ошибки в заметке, не меняя мысли и слов автора: длинный текст идёт в модель частями, а часть, которую модель переписала, остаётся как была. Итоги дня и недели пересказывают записи: у недели есть заголовок, рассказ, главное, темы и на что обратить внимание. В итогах учитываются настроение и оценки дней, которые поставил автор.

Недельный отчёт по задачам считается без нейросети и только по кнопке. Задача считается выполненной, когда попадает в колонку выполненных: время этого записывает триггер в базе, так что его ставит любое перемещение карточки. Колонку выполненных можно выбрать в кабинете, по умолчанию это последняя колонка доски.

Текст сначала сохраняется, а разбирается в фоне, поэтому сбой модели его не теряет. Очередь лежит в таблицах `diary_captures`, `diary_days`, `diary_summaries` и `task_captures`. В дневнике новые записи разбираются раньше итогов, у задач свой фоновый обработчик. Рассчитана она на один экземпляр сервера.

Подсказки для модели написаны по-русски, но ответ она пишет на языке записей: если они на английском, в конец подсказки добавляется требование отвечать по-английски. Язык аккаунта задаёт названия стартовых колонок и папки по умолчанию.

Каждый аккаунт выбирает модель сам. Локальная работает через [Ollama](https://ollama.com): `ORDEUS_AI_BASE_URL` задаёт адрес сервера, а `ORDEUS_AI_MODEL` — модель по умолчанию. Модель нужно скачать заранее:

```bash
ollama pull gemma4:12b
```

Удалённая подключается в личном кабинете по адресу OpenAI-совместимого API, ключу и названию модели. Модель должна поддерживать ответ в JSON. Текст записей при этом уходит вендору. Ключ шифруется на сервере и не возвращается в браузер, а адрес должен быть публичным `https`.

Голос всегда распознаётся локальной моделью, поэтому для него нужна Ollama даже при внешнем API.
